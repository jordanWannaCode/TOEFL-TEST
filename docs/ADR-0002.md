# ADR 0002 — Première tranche Reading persistante
Statut : accepté. Date : 13 octobre 2026.
Lecture du contenu approuvé via l'interface QuestionCatalog ; correction via SessionScorer. Le module examination ne dépend pas des implémentations internes de content et scoring. Les réponses sont privées par owner dérivé de l'identité serveur, jamais d'un champ envoyé par le navigateur.
JDBC rend explicites les requêtes et verrous ; les transitions et leur correction sont transactionnelles. Le verrou owner sérialise la création idempotente ; le verrou session sérialise sauvegarde, soumission et expiration. Version optimiste pour les onglets concurrents ; reçus idempotents pour une réponse HTTP perdue. response_events conserve les révisions successives sans modifier les réponses d'un examen fermé.
Le résultat objectif est un décompte de quatre unités pour le blueprint initial. Chaque blanc est une unité ; chaque QCM est une unité. Comparaison normalisée, aucun appel IA ni conversion en score ETS. Le rubric interne est versionné. Les clés sont séparées du contenu public ; elles ne sont chargées que pour la clôture et ne sont rendues qu'après état terminal.
Blueprints et révisions publiées immuables dans le parcours applicatif ; paramètre local de durée différent = nouvelle version, jamais modification d'une session active. Le blueprint est étiqueté CUSTOM_PRACTICE et ne prétend pas être validé par ETS.
Angular utilise le mode zoneless (signaux), des composants de type et une navigation réutilisable. Les réponses confirmées sont PostgreSQL ; les brouillons et requêtes en attente sont sessionStorage, scoped par utilisateur/session. Le compteur s'appuie sur heure serveur + temps monotone écoulé et reste indicatif.
Auth personnelle : Spring Security, cookie HttpOnly/SameSite, protection CSRF, mot de passe BCrypt. Cookie Secure par défaut ; désactivé seulement pour Compose local à ports loopback. Commercialisation : inscription, récupération de compte, throttling, politiques de conservation et sécurité publique à ajouter.
Tests isolés : toefl_test pour JUnit, projet Compose toefl-simulator-e2e pour le navigateur ; aucune tentative de test dans la base personnelle. MinIO est requis pour les futures tâches audio, pas pour cette tranche Reading.
