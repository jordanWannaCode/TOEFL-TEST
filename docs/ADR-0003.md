# ADR 0003 — Listening sur le moteur partagé
Statut accepté, 14 octobre 2026.
ReadingSessions/ReadingController deviennent ExamSessions/ExamController avec les mêmes routes. Sessions, réponses, événements, reçus idempotents et évaluations sont réutilisés. Les trois migrations antérieures restent inchangées ; V4 élargit les sections/types et ajoute médias privés, stimuli/transcripts, politiques et états/grants de playback.
Un stimulus et ses questions sont une révision de contenu atomique. Les clés et transcripts sont séparés du JSON public. La correction réutilise les comparaisons objectives existantes ; chaque question Listening vaut une unité interne, sans conversion officielle. Les statistiques regroupent par section.
MinIO est privé, derrière ObjectStorage. L'API vérifie owner et session avant chaque grant/requête audio ; les ranges d'une lecture utilisent le même grant. Les contrôles UI et le serveur appliquent la politique, sans promesse DRM. Le checkpoint pratique préserve la position ; en mode strict sans pause, le temps serveur écoulé borne la reprise pour ne pas recommencer un clip après refresh.
Les politiques sont figées dans la session depuis un blueprint versionné. La lecture unique est confirmée par ETS ; forward-only, reprise et durée de démonstration sont explicitement personnalisées. Un scheduler transactionnel expire et évalue les sessions sans dépendre du navigateur. Une stratégie adaptive NONE réserve la future sélection, sans simuler une adaptation.
Import local contrôlé et TTS derrière interface. Génération = DRAFT jusqu'à relecture ; immutable après publication. Le SDK MinIO 8.6.0 nécessite le module JVM explicite d'OkHttp 5.1.0 dans Maven. Aucun Redis, worker ou nouveau service métier n'est ajouté.
